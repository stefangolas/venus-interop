# Working on venus-interop

Notes for anyone, human or agent, changing this repository. Read [SPEC.md](SPEC.md) for the architecture and [docs/CONVENTIONS.md](docs/CONVENTIONS.md) for the rules the code implements.

## Ground rules

- **Never run `HxCfgFilConverter.exe`, or any Hamilton GUI tool, from scripts.** The converter sends `{ENTER}` to whatever window has focus. Everything it does, `files.hxcfg` does.
- **Never write into a Venus install or a user's labware folder.**
  - Tools write to a folder you give them.
  - Definition files from `plr.to_venus` / `deck_export` go to a `Labware\PLR\` folder the user installs.
  - `files.footer.rewrite` returns bytes; it doesn't touch files.
- **Lossless first.** Changing `files.*` must keep every corpus file byte-identical through read and write (`tests/test_hxcfg.py`, `tests/test_layout.py`, `tests/test_plr.py`).
- **No silent number changes.** Any conversion that alters a number or makes a choice records a `rules.deltas.Delta`. If you add one, add a test that a round trip's differences all match ledger entries (see `tests/test_deck_export.py::test_every_round_trip_difference_is_in_the_ledger`).
- **Rules are measured, not assumed.**
  - A new placement or naming rule needs corpus counts and named exceptions (`tests/known_exceptions.json`, regenerated by `tools/known_exceptions.py`; review its diff).
  - Write the rule into CONVENTIONS.md with its evidence.
- **Geometry alone doesn't make two labware the same.** Aliasing a Venus file to a PLR factory needs the same tip type, the same name, or a docstring naming the Hamilton file (`plr.name_match.alias_target`).
- **Say what's unverified.** Anything only Venus or the instrument can settle goes in CONVENTIONS §11 (open questions), not in code as fact.

## Layout and boundaries

- **No pylabrobot below `plr` and `multiflex.plr`.** `files`, `rules`, `multiflex.catalogue`, `multiflex.assembly` and `methods` use the standard library only, so they work without PLR installed.
- **Package data:**
  - `plr/templates/ML_STAR2.lay`: the STAR template; the STARlet is derived from it.
  - `plr/data/stock_map.json`: built by `tools/build_stock_map.py`.
  - `multiflex/data/mfx_catalogue.json`: Hamilton's `MultiMFX.INI`.
  - `methods/plld/PLLD_Speed.hsl`.
- **PLR conventions that matter here:**

| Convention | Detail |
|---|---|
| Carrier sites | Index 0 is the front; Venus site 1 is at the back |
| Coordinates | Rounded to 1e-4 |
| Model names | `model` often names a base factory |
| Embedded tip racks | Sit `sinking_depth` below their site |
| Tip spots | A tip spot is the tip's seat |

## Running things

```
.venv\Scripts\python -m pytest -q                         # quick: unit tests
set VENUS_INTEROP_CORPUS=<corpus folder>                  # the 152-layout corpus (tests skip without it)
set VENUS_INTEROP_NGS=C:\Users\stefa\NGS-Protocols        # NGS layouts and multiflex carriers
.venv\Scripts\python -m pytest -q -p no:cacheprovider     # full: about 1,550 tests, about 3.5 minutes
```

Windows shells mangle backslashes in inline Python (heredocs, `-c`). For anything with paths or escapes, write a `.py` file and run it.

## Where things come from

- **Corpora** (`venus_interop/corpora.py`):
  - lmsf_hamilton (GitHub): 141 layouts with their labware.
  - PyHamilton samples.
  - The local Venus install (`C:\Program Files (x86)\HAMILTON`).
  - NGS-Protocols (local).
  - Hamilton's shared library, downloaded by `plr-viz3d-scratch`.

  None is checked in: tests find them through environment variables.
- **Earlier work this repository gathers:**
  - `pressure_speed`: the converter, kept as it was.
  - `plr-viz3d-scratch/hamilton_library`: the multiflex catalogue, the 3D model conversion and the notes now in `docs/notes/`.
  - The `plr-viz3d` fork, branch `fork/viz3d-motion`: hand-written multiflex, ODTC, CPAC and heater-shaker factories, compared by `tools/mfx_reconcile.py`.

  Originals weren't changed.
