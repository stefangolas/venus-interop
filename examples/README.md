# Examples: hand-built PLR decks for Venus layouts

For a fresh GROQ setup, follow [the method workflow](../docs/METHOD_WORKFLOW.md): build a corpus,
generate a trace, then record or view the demo. The [Venus simulation harness](../tools/venus_sim/README.md)
documents the separate 1:1 position and firmware comparisons.

| File | Deck | Notes |
|---|---|---|
| `kapa_deck.py`, `kapa_compare_to_lay.py` | NGS STAR KAPA HyperPlus (`NGS-Protocols/protocols/KAPA_HyperPrep/KAPA_HyperPlus_Deck.lay`) | [docs/notes/VENUS_TO_PLR_kapa.md](../docs/notes/VENUS_TO_PLR_kapa.md) |
| `kapa_demo.py` | The same deck, running a slice of the protocol: a 96-head bead cleanup and an ODTC run | `--view` plays it in the 3D viewer; headless by default |
| `marionette_demo.py` | NIST LMSF "Marionette protease gradient plate prep v5", on its own imported deck | The whole method on a simulated STAR: plate and lid moves, media, salicylate, TMP, vancomycin, both serial dilutions, the plate map and worklist (`--plate-map FILE`); ends checking every well holds the same volume. `--view` plays it in the 3D viewer. Needs the layout corpus (`--corpus`) and the fork's `nist-viz` branch on `PYTHONPATH` |
| `groq_seq_demo.py` | NIST LMSF "GROQ-Seq.2_TFs" plate 1 and plates 2-5, on their imported deck | Both methods' `main` on the library ports, plate map and worklist included (`--plate-map FILE`). As committed, both abort in their plate-map code (a property read where none was set; an index from an unset variable), as Venus documents it, and run their abort handler; `--repair` fixes that code to give the intended worklist. Plates 2-5 end checking every well against the method's volume model (column 12 holds the TMP volume more: the method's own arithmetic). Needs the corpus and `venus-plr` |
| `dna_extraction_demo.py` | NIST LMSF "DNA Extraction", on its own imported deck, with a simulated MPE² | The whole method for one 24-sample set, elution through the MPE²: supernatant, P1/P2/N3, the wide-bore lysate transfer onto the filter, four presses and the elution press; ends checking 130 uL in each elution well. `--models DIR` draws the MPE² from `plr-models`' animated model (`mpe2_model.py`), moving as the simulation goes; `--view` plays it in the 3D viewer. Needs the corpus, the method's trace, and `nist-viz` (which has the MPE² package) |
| `kapa_hyperplus_demo.py` | KAPA HyperPlus library prep (`NGS-Protocols`, pyhamilton), the whole protocol, on its own imported deck | All six steps for 8 to 96 samples: fragmentation, end repair and A-tailing, ligation, both bead cleanups, amplification; the 96-head working from the CO-RE II tip support as pyhamilton's `TipSupportTracker` does, the ODTC served by the iSWAP (gripped from the right) with ComfortLids from the stack. Ends checking 20 uL of library in each well. Where the method cannot run as written (the empty nest it dispenses supernatant into, the index-primer source, step 6's arithmetic) the script says so as it goes. Needs the corpus, an NGS-Protocols checkout (`--ngs`) and `nist-viz` |
| `nist_deck.py`, `mpe2_model.py` | Shared by the NIST demos (`nist_deck.py` by the KAPA one too) | A layout imported and addressed by its sequences; the start deck from the method (`venus_interop.methods.deck_state`); moves that hand objects between placeholders; worklist writing and plate-map printing |
| `tc_deck.py` | The tissue-culture STARlet deck | [docs/notes/VENUS_TO_PLR_tissue_culture.md](../docs/notes/VENUS_TO_PLR_tissue_culture.md) |

These are the "physical" counterpart to the converter's faithful decks: one resource per physical object, built from pylabrobot factories. They import from the `plr-viz3d` fork at `fork/viz3d-motion` (multiflex, ODTC, CPAC, heater shakers) and from `plr-viz3d-scratch`, as they did where they were written. Run them in that environment, e.g. with `git archive fork/viz3d-motion pylabrobot` unpacked first on `PYTHONPATH`. They are kept as references, not tested here.

`kapa_demo.py` needs more than `fork/viz3d-motion`: it uses the CO-RE gripper, the tip support and the iSWAP collision check together, and as of 2026-10-16 only the uncommitted fork state of 2026-09-30 (kept as a stash on `viz3d-pr`) has all three. Run it on that tree, and with `--no-collision-check`: the ODTC's collision mesh is too coarse, so the check refuses the iSWAP's reach into it.
